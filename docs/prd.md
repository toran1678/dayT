# DayT 제품 요구사항 정의서 (PRD)

> **DayT** = **'Day'** + **'Date'**  
> 하루(Day) 전체를 책임지는 올인원 데이트(Date) 코스 추천 · 제작 · 기록 서비스

---

## 1. 프로젝트 개요 (Overview)

### 1.1 문제 정의 및 배경
- 데이트를 준비할 때 인스타그램·블로그에서 장소를 찾고, 지도 앱에서 거리를 재고, 메신저로 링크를 주고받으며 예산을 따로 계산해야 하는 **파편화된 탐색 피로감**이 존재함.
- 광고성 리뷰 속에서 실제 방문객의 핵심 포인트(`#주차가_편해요`, `#디저트_맛집` 등)만 빠르게 파악하기 어려움.
- 데이트가 끝난 뒤에도 코스와 추억을 한곳에 기록하고 커플이 함께 즐길 수 있는 지속적인 연결 고리가 부족함.

### 1.2 프로젝트 목표
1. **취향·예산·상황 맞춤형 탐색**: 지역, 데이트 테마, 음식 취향, 예산, 시간대, 날씨/분위기 키워드만으로 최적의 데이트 코스와 음식을 추천한다.
2. **직관적인 동선 설계 및 길안내 연결**: 지도 위 마커와 이동 경로(폴리라인)로 동선을 한눈에 검증하고, 원클릭 길안내(Google Maps Deep Link) 및 내 지도(KML)로 즉시 실행 가능하게 한다.
3. **함께 만들고 쌓아가는 커플 경험**: 실시간 공동 코스 편집, 카카오톡 공유, 만날 때마다 자라는 커플 펫(Grow Together), 데이트 일기장으로 데이트 전·중·후 경험을 하나로 연결한다.

## 2. 대상 사용자 (Target Users)

| 사용자 유형 | 특징 및 니즈 |
| :--- | :--- |
| **코스 고민형 커플** | "오늘 성수동에서 5만 원으로 뭐 하지?"처럼 지역·예산·음식 취향만 고르면 알아서 알찬 동선을 추천받고 싶은 사용자 |
| **계획형 코스 메이커** | 식당 → 카페 → 전시/영화관 순서를 직접 조합하고, 예상 이동 시간과 1인당 비용을 미리 시뮬레이션해 저장·공유하고 싶은 사용자 |
| **함께 정하는 커플** | 링크 하나로 연인과 동시에 접속해 장소를 실시간으로 넣고 빼며 코스를 함께 완성하고 싶은 사용자 |
| **기록·성장형 커플** | 만날 때마다 캐릭터를 키우고, 미니게임·미션을 즐기며 데이트 일기를 차곡차곡 남기고 싶은 커플 |

## 3. 화면 구조 및 페이지별 상세 구성 (IA & Screens)

> *(추후 기획 고도화에 따라 세부 화면 및 항목 확장 가능)*

### 3.1 인증 및 온보딩
- 카카오 / 구글 OAuth 소셜 로그인
- 닉네임 등 기본 프로필 설정 및 커플 연결(초대 코드/링크)

### 3.2 탐색 페이지 (`Explore` — 데이트 취향 설정 및 추천)
- **지역 / 지하철역 검색**: 특정 역이나 동네 입력 (예: 성수동, 홍대, 강남역 등)
- **데이트 테마 선택**: `감성 카페`, `맛집 투어`, `액티비티`, `전시·문화`, `산책·야외`, `어디든`
- **음식 취향 선택**: 대분류(`한식`, `중식`, `일식`, `양식`, `치킨`, `고기`, `분식`, `기타`) 및 세부 메뉴 추천 연동
- **오늘의 예산 설정**: 지출 희망 비용 범위 지정
- **데이트 시간 선택**: `반나절`, `하루 종일`, `저녁 데이트`
- **상황 키워드 조합**: `"비 오는 날"`, `"조용한 분위기"` 등 자연어/태그 조건 반영
- **탐색 결과 뷰**: 조건에 맞는 추천 장소·코스 리스트 + 선택한 장소와 이동 동선이 표시된 지도

### 3.3 코스 직접 만들기 페이지 (`Course Maker`)
- **코스 기본 정보**: 코스 제목 입력, 테마 태그 선택
- **장소 추가 및 순서 배치**: 마음에 드는 장소를 Pick하여 추가(위치, 예상 소비 비용 등)하고 방문 순서(`식당 → 카페 → 영화관` 등) 지정·변경
- **요약 지표 자동 계산**: 장소 간 예상 이동 시간, 총 데이트 소요 시간, **1인 예상 비용** 실시간 표시
- **동선 지도 프리뷰**: 선택한 장소 핀(마커)과 순서별 이동 경로(폴리라인) 지도 렌더링
- **코스 저장하기**: 완성한 코스를 내 코스로 DB 저장

### 3.4 저장한 데이트 코스 페이지 (`My Courses` — 내 코스)
- 내가 저장한 코스 목록 조회, 상세 보기, 수정 및 삭제
- **카카오톡 공유**: Open Graph 메타태그 기반 깔끔한 썸네일 카드 링크 공유
- **실시간 공동 편집 초대**: 공유 링크를 통해 상대방과 함께 장소 추가/삭제
- **외부 지도 연동**: 스마트폰 구글맵 원클릭 경유지 길안내 실행, 구글 '내 지도(My Maps)' 임포트용 KML 파일 다운로드

### 3.5 GROW TOGETHER 페이지 (커플 성장 & 인터랙션)
- **성장형 커플 펫**: 커플이 만날 때마다(하루 단위 인증/기록) 경험치를 얻어 캐릭터가 단계별로 성장
- **오늘의 성장 미션**: 데이트 중 함께 달성할 수 있는 일일 미션 제공
- **커플 미니 게임**: 데이트 메뉴 고르기, 밸런스 게임 등 둘이서 가볍게 즐길 수 있는 미니 게임

### 3.6 데이트 일기장 페이지 (`Date Diary`)
- 날짜별 데이트 일기 목록 및 타임라인 조회
- **일기 작성**: 날짜, 제목, 본문 내용, 사진 첨부 (다녀온 데이트 코스 연동 가능)

### 3.7 반응형 레이아웃 및 외부 공유 뷰어 (`Web-First Responsive` & `Mobile 확장`)
- **데스크톱 · 모바일 완벽 반응형 지원 (`web/` — Next.js 주력 클라이언트)**:
  - **데스크톱 뷰**: 좌측 사이드바 네비게이션 + 상단 검색/상태 바 + 넓은 지도·카드 대시보드 레이아웃
  - **모바일 웹 뷰**: 스마트폰 브라우저(카카오톡 인앱 브라우저 등) 접속 시 하단 고정 탭바(Bottom Navigation)와 터치 친화적 풀스크린 레이아웃으로 자동 전환되어 네이티브 앱과 동일한 사용성 제공
- **공유 및 협업**: 공유 링크 접속 시 Open Graph 메타태그 프리뷰 및 별도 설치 없는 실시간 공동 코스 편집 지원
- **모바일 네이티브 확장 (`mobile/` — 추후 확장)**: 웹 MVP 완성 후 동일한 API 계약·타입·비즈니스 로직을 재사용하여 React Native(Expo) 앱으로 이식 가능

## 5. 데이터 수집 및 AI 추천 파이프라인 설계

사용자 검색 시 실시간 크롤링을 수행하면 응답 지연(수십 초) 및 차단 위험이 발생하므로, **"사전/백그라운드 데이터 수집·가공(Offline)"** 과 **"실시간 후보 필터링 및 AI 코스 조합(Online)"** 두 단계로 분리해 설계한다.

### 5.1 데이터 출처별 역할 분담

무작위 스크래핑을 최소화하고 **공식 오픈 API를 기본 뼈대**로 삼아 안정성을 확보한 뒤, 부족한 분위기·가격·리뷰 요약만 선택적으로 보강한다.

| 데이터 구분 | 추천 수집처 (우선순위 순) | 확보 데이터 | 수집 방식 |
| :--- | :--- | :--- | :--- |
| **① 장소 기본 정보 (뼈대)** | **카카오 로컬 API** (키워드/카테고리 검색)<br>**네이버 지역 검색 API** | 장소명, 도로명 주소, 정확한 위도·경도, 전화번호, 세부 업종(`일식 > 돈카츠`), 상세 URL | 공식 REST API<br>(실시간 조회 + DB 적재) |
| **② 전시·축제·팝업** | **한국관광공사 TourAPI 4.0**<br>**공공데이터포털** (`전국문화축제표준데이터`)<br>서울 열린데이터광장 (문화행사 API) | 진행 중인 지역 축제, 전시회, 공연·행사 기간, 장소 좌표, 대표 포스터 이미지, 이용 요금 | 공식 REST API<br>(일/주 단위 정기 배치 수집) |
| **③ 리뷰·분위기·예상 가격** | **1순위: 네이버 블로그 검색 공식 API**<br>**2순위: Google Places API (New)**<br>**3순위: 플레이스 웹 페이지 보조 수집** (`Playwright`) | 방문객 후기 요약문, 가격대(`priceLevel`), 영업시간, 분위기 키워드, 대표 메뉴 및 가격 | 백그라운드 비동기 수집 후<br>Gemini로 JSON 요약 저장 |

> **설계 유의사항 (스크래핑 범위 제한):**  
> 인스타그램 등은 로그인 강제 및 봇 차단이 매우 엄격하여 유지보수 비용이 과도함. 따라서 핫플레이스·전시 정보는 **TourAPI + 네이버 블로그 검색 API** 조합을 주력으로 사용하고, `Playwright` 기반 수집은 핵심 데이트 상권(성수, 홍대, 연남, 강남 등)의 부족한 상세 정보(메뉴 가격 등)를 보강하는 **배치 작업용 보조 수단**으로 제한한다.

### 5.2 수집부터 사용자 추천까지 5단계 흐름 (End-to-End Flow)

#### [A. 사전 · 백그라운드 수집 파이프라인 (`ai-service`)]
1. **Step 1 — 기본 장소 풀(Pool) 확보**: 주요 데이트 상권(역/동네) × 카테고리별로 카카오 로컬 API 및 TourAPI를 호출해 `Place` 테이블에 기본 정보와 위·경도를 저장한다. *(DB에 없는 신규 지역을 사용자가 검색하면 공식 API로 즉시 조회 후 DB에 자동 추가)*
2. **Step 2 — 리뷰 텍스트 수집**: 저장된 장소명으로 네이버 블로그 검색 API(및 보조 수집기)를 호출해 상위 후기 텍스트·스니펫 5~10건을 수집한다.
3. **Step 3 — Gemini 기반 정형 JSON 가공 및 해시태그 저장**: 수집한 비정형 후기 텍스트를 **Gemini API (Structured Outputs)** 에 전달해 아래 형태의 요약 데이터로 변환한 뒤 DB에 저장한다. (원문 대신 가공된 태그·가격만 저장해 재사용)
   ```json
   {
     "hashtags": ["#조용한_분위기", "#비오는날_추천", "#디저트_맛집", "#주차_편함"],
     "avg_price_per_person": 18000,
     "indoor": true,
     "recommended_menus": ["연어 덮밥", "모찌리도후"],
     "one_line_summary": "아늑한 우드톤 인테리어로 대화 나누기 좋은 일식당"
   }
   ```

#### [B. 실시간 사용자 코스 추천 파이프라인 (`mobile` ↔ `backend` ↔ `ai-service`)]
4. **Step 4 — DB/Redis 기반 1차 후보군 고속 필터링**:
   - 사용자가 앱에서 조건(예: `성수동` + `맛집 투어 & 감성 카페` + `일식` + `예산 5만 원` + `저녁 데이트` + `"비 오는 날"`)을 입력한다.
   - 먼저 Redis 캐시에 동일 조건 추천 결과가 있는지 확인하고, 없으면 DB에서 해당 지역 반경(예: 1.5km) 내 조건에 부합하는 후보 장소 20~30곳(식당·카페·실내 볼거리)을 1차 필터링한다. *(DB에 실제로 존재하는 장소만 추려내어 LLM의 가짜 장소 환각(Hallucination)을 원천 방지)*
5. **Step 5 — Gemini 최적 동선 조합 및 지도 렌더링**:
   - 추려진 20~30개 후보 장소의 요약 정보(좌표, 1인 예상 비용, 해시태그, 실내 여부)를 **Gemini API**에 전달한다.
   - Gemini가 **총예산 한도 충족 여부**, **상황 적합도(비 오는 날 → 실내 위주)**, **장소 간 이동 거리 최소화(`식당 → 카페 → 놀거리` 순차 동선)** 를 계산해 최종 추천 코스(3~4곳 조합 + 코스 설명)를 JSON으로 반환한다.
   - 앱(`mobile`)은 반환된 순서대로 지도 위에 마커와 이동 경로(폴리라인), 예상 소요 시간·총비용을 즉시 렌더링한다.

## 6. 데이터베이스 모델링 초안 (ERD Concept)

> 상세 컬럼 타입 및 제약조건은 추후 `docs/erd.md`에서 확정한다.

- **`User` (사용자)**: 사용자 ID, 닉네임, 이메일, OAuth 제공자(카카오/구글) 및 식별자
- **`Couple` (커플 연결 - 확장)**: 두 `User` 간 매칭 정보, 공유 펫/일기장 연결 기준
- **`Place` (장소)**: 외부(카카오/네이버) 장소 ID, 장소명, 위도/경도, 카테고리, 주소, 대표 이미지 URL, 요약 해시태그
- **`Course` (코스)**: 코스 ID, 코스 제목, 테마 태그, 작성자 ID, 총 예상 비용, 총 예상 소요 시간, 데이트 시간대
- **`Course_Place_Mapping` (코스-장소 매핑)**: `Course` ↔ `Place` N:M 해소 테이블, 방문 **순서(`Order`)**, 장소별 예상 지출 비용, 체류/이동 메모
- **`Pet` / `Mission` (Grow Together)**: 커플 펫 레벨·경험치, 마지막 만남 인증일(하루 단위 성장), 일일 미션 달성 상태
- **`Diary` (데이트 일기장)**: 일기 ID, 작성자/커플 ID, 데이트 날짜, 제목, 내용, 이미지 목록, 연관 코스 ID(선택)

## 9. 확정된 아키텍처 결정 및 추후 구체화 포인트

### 9.1 확정된 핵심 기술 의사결정
1. **메인 RDBMS**: **PostgreSQL (`PostGIS` + `JSONB`)** — 반경 기반 장소 공간 탐색 및 AI 요약 해시태그 유연 저장
2. **프론트엔드 개발 전략 (`Web-First` + 모바일 반응형)**: **Next.js (App Router + TypeScript + Tailwind CSS)** 로 데스크톱 대시보드와 모바일 앱형(하단 탭바) 반응형 웹을 먼저 완성하고, 이후 동일한 API 타입·로직을 재사용해 **React Native (Expo)** 네이티브 앱으로 확장
3. **메인 지도 연동**: **Google Maps JS API (앱 확장 시 `react-native-maps`) + 카카오 로컬/모빌리티 API** — 서비스 무드 커스텀 테마 맵 스타일 통일 및 국내 상권 POI/동선 정확도 확보

### 9.2 추후 구체화할 기획 포인트
1. **초기 시드(Seed) 상권 범위**: MVP 출시 시 사전 수집해 둘 초기 핵심 데이트 상권(예: 성수, 홍대, 연남, 강남, 잠실, 혜화 등) 목록 확정
2. **음식 추천 및 커플 미니게임 세부 기획**: 룰렛/토너먼트/취향 매칭 등 구체적인 인터랙션 방식 확정
